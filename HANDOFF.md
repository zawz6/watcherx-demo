# WatcherX demo: hand-off

Clickable Arabic (RTL) demo of WatcherX for the Second Industrial City, Riyadh. **Tier 1**: every number comes from simple rules on synthetic data, not from trained models. Repo: `zawz6/watcherx-demo` (private).

## Run it

```bash
cd web && pnpm install && pnpm dev          # http://localhost:3000
pnpm build && npx serve out -l 3100          # production build (static export), used for screenshots
BASE=http://localhost:3100 node scripts/screenshots.mjs   # writes ../shots/ss01..ss10 (1920x1080)
BASE=http://localhost:3100 node scripts/flow-test.mjs     # 15 interaction checks
cd ../data-gen && uv run python generate.py  # regenerates web/public/data/*.json (seed 42, about 2 s)
```

The basemap (CARTO Dark Matter) needs internet. Keep its attribution visible and check its usage terms before a public launch.

## Numbers for the deck (hand-off H2)

**How they were produced:** `data-gen/generate.py`, seed 42, **rule-based** (the multipliers in the demo spec §6.3), not LightGBM or OR-Tools. 185 H3 zones, 180 days of synthetic incidents, 6 patrol cars on the night shift. The test window for the hit rate is 2026-10-22..2026-11-20 (151 incidents).

**Label rule:** every number below is shown in the demo as «أرقام توضيحية على بيانات افتراضية». The shared brief's numbers rule is relaxed on this basis: use them in the deck only with that label.

| Metric | Proposed (WatcherX) | Current fixed plan |
|---|---|---|
| Coverage of level 4–5 zones (zones that get a scheduled visit tonight) | 100% | 50% |
| Average response time | 3.9 min | 4.3 min |
| Worst-10% response time (p90) | 6.6 min | 7.7 min |
| Hit rate: incidents in the top 10% riskiest zones | 22.5% | 18.5% («بؤر الشهر الماضي» baseline) |

Last 4 weeks (M2 tiles, replaying each week's night incidents): average response 3.9 min vs 4.5 min on the current plan (-14%); incidents in the last 30 days 151 vs 113. The approval rate (81%) is a scripted usage figure, not measured.

**Be honest about:** the hit-rate gap is modest (22.5% vs 18.5%) and the data are synthetic, generated by the same rules the score uses. Do not present it as a validation result.

## Demo settings (assumptions, not MODON facts)

6 / 4 / 3 cars on night / evening / morning shifts. Car speed 30 km/h on straight-line distance × 1.3 + 1 min dispatch. Shifts 06–14, 14–22, 22–06. "Now" is Saturday 21 Nov 2026, 21:40. Holiday dates are approximate (Eid al-Adha 26–30 May, National Day 23 Sep).

**Coverage definition.** The spec defines coverage as high-risk zone-hours within 10 minutes of a car. The city is compact enough that both plans reach 100% under that rule, so the demo reports the share of level 4–5 zones that receive a scheduled patrol visit instead. The 10-minute target is still listed as a setting. Change `evaluate()` in `generate.py` if you prefer the original definition.

**Repeat pattern.** Tonight's plan puts the riskiest zone at 22:00 on 7 of the last 7 replayed nights (Z147), so the warning is real, not scripted. Two alternative windows are shown.

**Manager story.** Northern thefts rose after two sites closed (24 and 29 Oct) and a lighting fault began on 27 Oct. Those causes are built into the generator, so the chat answer matches the data.

## Known limits

- Chat answers are scripted. Free typing needs 2 or more keyword hits, otherwise the agent says it only answers the suggested questions.
- Only the night plan is generated; morning and evening show forecasts but no plan.
- No live backend and no LLM: the agent trace is a recorded replay of the steps.
